W включает набор защит на каждой установке и даёт переключатели там, где
это имеет смысл настраивать. Графические элементы управления собраны в
**Хаб → Система → Безопасность**.

## Что включено по умолчанию

- **Защита ядра** — подобранная затяжка sysctl и параметров командной строки
  штатного ядра (`w-kernel harden status`). Это переключатель, не форк:
  повседневное ядро остаётся отзывчивым.
- **sudo-rs** как инструмент повышения прав, привычный `sudo` работает так же
  — запросы на повышение выглядят как на любой системе Arch.
- **Шифрованный DNS** — systemd-resolved резолвит через TLS у провайдера,
  уважающего приватность (по умолчанию Quad9). `w-dns` меняет провайдера или
  режим.
- **Фаервол** — firewalld с backend'ом `nftables` и разрешительной зоной по
  умолчанию, подходящей для домашней сети. `w-firewall public|home`
  переключает машину между зонами; в **Хаб → Сеть** те же выпадающие списки.
- **Keyring** — gnome-keyring хранит секреты пользователя (Wi-Fi, сохранённые
  пароли); сторона SSH-агента — нейтральный слот (`w-ssh`), который работает
  с любым backend'ом.
- **Обновления прошивки** — `fwupd` и его таймер; `fwupdmgr refresh &&
  fwupdmgr update` применяет их.

## Песочница для приложений (опционально)

Сторонние графические приложения лучше запускать в песочнице, и W держит
готовыми нужные для этого слоты — десктопные порталы и непривилегированные
пользовательские namespace'ы ядра включены из коробки. Сам канал доставки —
по запросу: `sudo w-pack install flatpak` добавляет Flatpak с репозиторием
Flathub, магазин **Bazaar**, **Flatseal** для прав приложений и тему W внутри
песочницы. Устанавливайте, если нужна эта экосистема; машине, которая берёт
софт из репозиториев, это не требуется.

## Вход по отпечатку

Если у машины есть считыватель отпечатков, `w-fingerprint` записывает ваши
пальцы, и экран входа, экран блокировки и запросы повышения прав примут их.
**Хаб → Ввод → Отпечаток** делает то же самое графически.

Та же панель решает, как сканер ведёт себя под экраном блокировки. По
умолчанию он горит всю блокировку, и палец проверяет сам hyprlock. Некоторые
ридеры от этого перегреваются и через несколько минут перестают отвечать; для
них выберите **Сканер → По активности** (`w-fingerprint lock-sensor mode
wake`): сканер загорается на короткое окно после блокировки, пробуждения или
любой активности под блокировкой, затем гаснет. Окно настраивается (10–300 с);
изменение действует со следующей блокировки.

## Шифрование диска и Secure Boot

Установщик первым предлагает зашифрованный диск, и это рекомендуемый выбор —
особенно на ноутбуке. Шифруется весь системный раздел (LUKS2): украденный
ноутбук или извлечённый диск без пароль-фразы ничего не раскроют.
Работающую разблокированную систему шифрование не защищает — это задача
блокировки экрана и остальных слоёв на этой странице.

**Почему пароль спрашивается при каждой загрузке.** Пока вы не решили иначе,
пароль-фраза — единственный ключ. Автоматическая разблокировка безопасна только
вместе с Secure Boot, поэтому установщик включает её лишь тогда, когда Secure
Boot уже включён в прошивке, и только на настольном компьютере (см. *Установка с
включённым Secure Boot*); в остальных случаях решение за вами, в установленной
системе.

**Автоматическая разблокировка (Secure Boot + TPM2).** Чип TPM2 может хранить
ключ диска и отдавать его только знакомой цепочке загрузки. Без Secure Boot
эта проверка ничего не значит — TPM отдаст ключ любой флешке, с которой
загрузятся, — поэтому W включает их в одном порядке: сначала Secure Boot,
потом TPM2.

**Secure Boot включается в двух местах.** Одного переключателя в настройках
прошивки (BIOS) мало, чтобы W загрузилась: сначала W готовит свою цепочку — свой
ключ и подписанный загрузчик с отпечатком меню. Строка **Secure Boot** в
**Хаб → Система → Безопасность** показывает, где сейчас машина, и называет
следующий шаг: подготовить W, перезагрузиться, включить Secure Boot в прошивке
(строка умеет перезагрузить сразу в настройки прошивки), завершить. Из терминала
это `sudo w-secureboot enable` — один раз до перезагрузки и один раз после.
Путь зависит от прошивки:

- **Заводские ключи (обычный случай).** W загружается через подписанный
  Microsoft *shim* и добавляет свой ключ с вашего подтверждения: после первого
  шага перезагрузитесь — синее меню *Shim UEFI key management* откроется само.
  Выберите **Enroll MOK → Continue → Yes**, введите одноразовый код из
  терминала (при вводе он не отображается) и **Reboot** — в пределах 5 минут,
  иначе прошивка перезагрузит компьютер и запрос пропадёт. Никогда не
  выбирайте **Reset MOK**: он стирает все занесённые ключи. Вместо этого
  загрузилась Windows? Выберите **W** в меню загрузки прошивки (F11/F12/Esc)
  и поставьте её первой в порядке загрузки прошивки. Затем включите
  Secure Boot в прошивке, если он ещё не включён, и завершите включение.
  Если прошивка не доверяет стороннему сертификату Microsoft
  (часть ноутбуков «Secured-core»), W скажет об этом: включите *Allow
  Microsoft 3rd-party UEFI CA* в настройках Secure Boot прошивки.
- **Прошивка в Setup Mode** (ключи вы очистили сами). W заносит свои ключи;
  один раз перезагрузитесь и завершите.

**Затем — автоматическая разблокировка, отдельно.** Включение Secure Boot само
её не добавляет — это строка **Автоматическая разблокировка (TPM2)** под ним,
заблокированная, пока Secure Boot не включён в W и в прошивке:

- **TPM** — диск открывается без вопросов, пока цепочка загрузки — W.
- **TPM + PIN** — TPM по-прежнему проверяет цепочку загрузки и вдобавок
  спрашивает короткий PIN. Под полем ввода PIN — значок клавиатуры. Забыли PIN?
  После трёх неверных клавиатура сменится замком: в это поле вводится
  пароль-фраза или ключ восстановления. Тот же замок появляется сразу, если
  изменилась цепочка загрузки. Пароль-фраза, введённая в поле с клавиатурой,
  считается неверным PIN.
- **Выкл** — пароль-фраза при каждой загрузке.

Любой выбор один раз спросит текущую пароль-фразу в терминале. После
обновления прошивки или shim — или когда Windows на этом же компьютере
ставит обновления Secure Boot от Microsoft (она делает это только при
включённом Secure Boot) — TPM перестаёт узнавать цепочку: диск один раз
спросит пароль, а строка предложит **Перепечатать** (`sudo w-crypt
reenroll-tpm`). Из терминала: `sudo w-crypt enroll-tpm` (`--pin` — с PIN),
`sudo w-crypt wipe-tpm` — выключить.

**Выключение Secure Boot** идёт в обратном порядке: сначала прошивка (с
заводскими ключами W загружается только через shim), затем **Отключить в W** в
той же строке. Оно снимает и автоматическую разблокировку — пароль снова будет
спрашиваться.

**Windows с BitLocker рядом с W.** Первый путь ключи прошивки не трогает —
Windows ничего не заметит. Свои ключи W меняют то, что измеряет BitLocker, и
Windows один раз спросит ключ восстановления — держите его под рукой. То же
самое вызывает выключение Secure Boot в прошивке.

**Меню загрузки опечатано.** При включённом Secure Boot загрузчик хранит
отпечаток своего меню и не стартует, если меню изменили в обход него. Свои
изменения W сопровождает новым отпечатком и сверяет его ещё раз перед каждым
выключением, перезагрузкой и гибернацией, так что подхватывается и правка
вручную. Устаревшим отпечаток может оставить только отключение питания или
жёсткий сброс сразу после изменения — путь назад описан в `RECOVERY.md`
(*CHECKSUM MISMATCH FOR CONFIG FILE*).

- **Стоит включить** на настольном компьютере с чипом TPM2: извлечённый из
  машины диск остаётся нечитаемым, а пароль вводить больше не нужно.
- **TPM + PIN** — на ноутбуке, который вы носите с собой: с одним TPM
  украденный ноутбук загрузится до экрана входа, и между вором и файлами
  останется только пароль учётной записи. С PIN загрузка остановится до
  открытия диска, а TPM блокируется после нескольких неверных попыток — короткого
  PIN достаточно.
- **Остаться на пароле** — если в машине нет TPM2, если ключ должен
  существовать только в вашей голове или вы часто меняете настройки прошивки.

Сохраните пароль-фразу и при автоматической разблокировке: она понадобится
снова при любом изменении прошивки или Secure Boot. Строка **Ключ
восстановления** (или `sudo w-crypt recovery-add`) добавляет длинный ключ для
печати — второй запасной: он показывается один раз, в терминале, а
**Заменить** меняет его на новый. Он работает везде, где пароль-фраза, — в поле
с замком при загрузке или при открытии диска с live-флешки, — поэтому выручит,
если пароль забыт, если TPM перестал узнавать машину или диск переехал в другой
компьютер. Храните оба вне этого компьютера.

### Установка с включённым Secure Boot

Установочный носитель W стартует с включённым Secure Boot. Он грузится через
подписанный Microsoft *shim*, а shim доверяет загрузчику W по его отпечатку —
его вы добавляете один раз на каждый скачанный образ:

1. Загрузите носитель. Этот образ shim ещё не знает: появится `Verification
   failed`, затем синий экран *Shim UEFI key management*. Он ждёт только 10
   секунд — нажмите любую клавишу. Не успели — перезагрузитесь и повторите.
2. Выберите **Enroll hash from disk**, носитель, затем `EFI/BOOT/grubx64.efi`.
   Перед **Continue** сверьте хэш, который показывает MokManager, с *Secure Boot
   hash* на странице загрузки — именно ему прошивка начнёт доверять. Затем
   **Continue → Yes → Reboot**. Пароль не нужен.
3. Теперь носитель запускает установщик. Более новый образ — другой файл и
   спросит ещё раз; старый отпечаток не мешает.

При включённом Secure Boot проверяется весь носитель: изменённый образ
остановится до запуска установщика. Прошивка, доверяющая только Windows
(часть ноутбуков «Secured-core»), отвергает носитель сразу — `Access Denied` или
экран нарушения Secure Boot. Включите *Allow Microsoft 3rd-party UEFI CA* в её
настройках Secure Boot или выключите Secure Boot на время установки; в обоих
случаях Windows с BitLocker один раз спросит ключ восстановления.

При включённом Secure Boot предлагается только зашифрованная установка, и
установщик сам настраивает Secure Boot для установленной системы (путь через shim,
описанный выше). Вам остаётся один шаг — при первой загрузке после установки:

1. Последний экран установщика показывает одноразовый код. Перезагрузитесь:
   синее меню *Shim UEFI key management* откроется само.
2. **Enroll MOK → Continue → Yes**, введите код (при вводе он не отображается).
   Так добавляется собственный ключ установленной системы — без него W при
   включённом Secure Boot не запустится.
3. **Delete MOK → Continue → Yes**, тот же код. Так удаляется отпечаток
   носителя, который вы добавили, чтобы запустить установщик: установленной W
   он не нужен, а оставленный — держал бы этот публичный образ доверенным для
   вашей прошивки. У более нового образа отпечаток всё равно другой — носитель
   спросит снова, если загрузите его позже. Нет **Delete MOK** в списке —
   пропустите шаг.
4. **Reboot.**

Уложитесь в 5 минут — иначе прошивка перезагрузит компьютер и запрос пропадёт.
Никогда не выбирайте **Reset MOK**: он стирает все занесённые ключи. Если
запрос пропал, меню вернётся после *Verification failed* с 10-секундным
отсчётом — нажмите любую клавишу, затем **Enroll key from disk → W_EFI
(системный диск) → EFI → W → W-MOK.cer → Continue → Yes → Reboot**, код не
нужен. Отпечаток носителя тогда останется — вреда от него нет.

Некоторые прошивки не принимают запрос вовсе: работающей системе они не дают
создавать новые переменные и принимают их только от синего экрана при загрузке
(встречается на старых платах с AMI, например серии ASUS X99). Установщик это
замечает, и на его последнем экране вместо кода — только шаги: перезагрузитесь,
нажмите любую клавишу, когда после *Verification failed* появится меню, затем
**Enroll key from disk → W_EFI → EFI → W → W-MOK.cer → Continue → Yes →
Reboot**. Отпечаток носителя в этом случае тоже остаётся — для его удаления
нужен тот же отвергнутый запрос.

Дальше W завершает установку уже с включённым Secure Boot. На настольном
компьютере с чипом TPM2 диск с этого момента открывается сам; ноутбук продолжает
спрашивать пароль — **Хаб → Система → Безопасность → Автоматическая
разблокировка** добавит TPM + PIN (или TPM), если она нужна и там.

## Управление ядром

`w-kernel` меняет активное ядро (default, LTS, vanilla) и переключает
профиль защиты. Оба живут в Хабе; смена ядра предлагает аккуратную
перезагрузку, когда работающее ядро изменилось.

## Что пока не защищено

USB-карантин (USBGuard) спроектирован, но опционален и пока не поставляется
— подключённое чужое USB-устройство сейчас доверенное, как любой другой
накопитель. Снапшоты — ответ на неудачное обновление, а не резервная копия:
если диск потерян или вышел из строя, откатываться будет не к чему.
Резервируйте всё, что не сможете воссоздать сами.
