`w-conf` — Чтение и запись слоёной конфигурации W (вендор → админ → пользователь).

## Использование

```
Использование: w-conf <команда> [параметры]

Info: Чтение и запись слоёной конфигурации W (вендор → админ → пользователь).

Команды:
  get <подсистема> <ключ> [default]  Напечатать действующее значение
  origin <подсистема> <ключ>         Победивший слой (--path: его файл)
  list [<подсистема>]                Напечатать KEY=VALUE (без неё — их список)
  cat <подсистема>                   Разбор: слои, файлы, победитель по ключам
  layers <подсистема>                Цепочка слоёв и какие файлы существуют
  scope <подсистема> [<ключ>]        Кто может задать ключ: system | user | both
                                     (без ключа: KEY<TAB>область по подсистеме)
  set <подсистема> <ключ> <знач>     Записать в системный слой (--user: юзера)
  unset <подсистема> <ключ>          Убрать ключ из слоя (--user аналогично)
  help                               Показать эту справку

Параметры:
  --user            Работать со слоем пользователя (~/.config/w) вместо /etc/w
  --user-of <имя>   Смотреть/писать слой ЭТОГО пользователя (root по умолчанию
                    берёт вызывающего — так же, как читают сами подсистемы)
  --porcelain       list: KEY<TAB>VALUE<TAB>LAYER<TAB>locked<TAB>SCOPE (для GUI)
  --prefix <P>      list/cat: только ключи, начинающиеся с P (например, NTP_)
  --path            origin: напечатать победивший файл, а не имя слоя
  --                Завершить разбор параметров; нужно перед <знач>, которое
                    само начинается с '-' (например, строка флагов comfyui.ARGS)

Коды выхода:
  0  Успех
  1  Ошибка выполнения (слой недоступен для записи, ключ заперт политикой,
     недопустимое значение)
  2  Ошибка вызова

Примеры:
  w-conf get power CHARGE_LIMIT
  w-conf origin ai HOST
  w-conf cat power
  w-conf list time --prefix NTP_
  sudo w-conf set power CHARGE_LIMIT 80
  w-conf set comfyui ARGS -- "--lowvram --cpu-vae"
```

версия того же текста на машине с W: `w-conf help`.
